UID/GID 10001, Next standalone, injected `PORT=10000`, `HOSTNAME=0.0.0.0` and a
PORT-aware health probe. EXPOSE 3000 is metadata/local default. No application,
domain, model, timeout, consent, eligibility or business-logic change was needed.

The local checker gained an isolated Render profile: 512 MiB, 0.1 CPU, host
8082 → container 10000, empty keys, no volume, the existing 384-MiB V8 heap
setting, selected resource/state evidence and cleanup by its exact created ID.
Its longer cold-local-health/browser wait changes no application deadline.
The deployment-only fake S1 harness now uses FakeTts and DATA_DIR, and runs twice
inside this constrained container. These bundles do not enter the runtime image.
Five Render-origin regression cases supplement existing Host/Origin guards.

`PROXY_MODE=caddy` names the existing conservative implementation; no Caddy
process is deployed. Exact generated `DOMAIN` permits public HTTPS Origin after
internal HTTP normalization. Missing/malformed DOMAIN fails closed for that
public HTTPS request. Foreign Host/Origin and forged forwarding headers cannot
grant trust; caller-supplied XFF does not become identity. All unverified clients
share a rate-limit bucket, so concurrent evaluators can block one another.

HTTP startup/health does not synthesize. With both keys and no access gate, the
first dynamic homepage request can start one greeting TTS plus six English
recovery-clip syntheses, subject to existing retry/failure policy. Process caches
are lost on sleep/restart, allowing fresh charges. This was inspected, not invoked.
Provider flags only indicate configuration. Real-call memory remains unknown.

## Manual release gates and remaining uncertainty

The reviewed revision must be pushed separately before Render's GitHub `main`
build can include it. Publication is not authorized by this task. The operator
then selects one **Free** Docker Web Service, Singapore only if actually offered
on Free (otherwise stop and ask), root Dockerfile/context, default CMD,
`PORT=10000`, exact generated hostname and health `/api/health`. Provider keys
are entered manually only when the operator chooses that separate usage.

[Official Free limits](https://render.com/docs/free) and the
[first-deploy tutorial](https://render.com/docs/your-first-deploy) support a no-card
attempt, not a verified account entitlement or deployment. The runbook records
512 MB/0.1 CPU, workspace-shared allowances (750 running instance hours, Hobby
5 GB outbound and 500 pipeline minutes), sleep/wake and no-card exhaustion
suspension/build-disable behavior. A card or paid-upgrade demand means stop;
never attach one or silently switch compute. Provider charges remain separate.

Actual Render edge SSE, account/region eligibility, public HTTPS/origin behavior,
mobile data, live provider reliability/latency, peak memory, physical audio and
public no-secret logs are untested. Local streaming tests are not proof of the
public edge. Complete the runbook's real stream-reader and full consent/S1 checks
before claiming a successful deployment. Record actual first-audio samples and
measurement boundary; no invented latency threshold.

Free sleep/restart/deploy can erase sessions, temporary JSONL ledger, counters and
caches. No persistent disk or uptime pings. If constrained or public acceptance
fails, stop without a paid upgrade; recommend laptop-hosted Tailscale Funnel for
separate review and retain local Compose. Nothing launches that fallback here.

Teardown is operator-only: disable Auto-Deploy, delete only SellerSaathi's service,
check workspace usage/invoices and absence of extra resources, revoke this repo's
Render authorization and publicly used provider credentials when no longer needed.
Keep the repo, local project, unrelated resources and account intact.
